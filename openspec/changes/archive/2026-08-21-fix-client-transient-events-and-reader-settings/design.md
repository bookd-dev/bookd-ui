## Context

客户端共享层当前同时存在两类生命周期错配：一次性 Snackbar 错误被持久状态流重放；阅读器设置则只存在于 ViewModel 内存并依赖 500ms 后的远端请求。Compose 页面与 Android 配置可以独立重建，ViewModel 也可能在导航退出时清理，因此短暂事件和持久偏好需要采用不同的数据语义。

## Goals / Non-Goals

**Goals:**

- 让全局错误在暂无 UI 订阅者时可缓冲，并在首次消费后不再重放。
- 让阅读器设置在用户操作返回前同步写入跨平台本地存储。
- 保留远端防抖和最新值合并，避免连续滑动产生请求风暴或旧响应覆盖新设置。

**Non-Goals:**

- 不改变服务端阅读器设置接口或 DTO。
- 不改变阅读器设置面板的视觉与交互范围。
- 不把 Snackbar 历史恢复为可回放通知列表。

## Decisions

### 1. 使用缓冲消费流承载一次性全局错误

全局错误写入有界缓冲通道并作为消费流暴露。未开始收集时事件留在缓冲区；收集器取得事件后即从队列移除，所以页面重建不会再次收到旧错误。相比继续使用状态流并手动清空，该方案不会在 Snackbar 挂起显示与配置重建之间产生“何时清空”的竞态。

### 2. 阅读器设置采用本地优先、远端最终同步

ViewModel 接受设置后直接调用仓库的同步本地写入，再启动已有的 500ms 防抖同步。仓库将设置 DTO 序列化到跨平台 Settings，并维护待同步标记。重新进入阅读器时，待同步本地值优先返回并重新加入远端同步队列。

### 3. 仅确认仍是当前值的远端响应

远端更新完成后，仓库比较请求快照与当前本地快照。只有两者相等时才用服务端响应确认本地缓存并清除待同步标记；如果用户已产生更新值，则保留新值和待同步状态，由单飞队列继续提交最新快照。

### 4. 使用现有共享 Settings 实例

阅读器仓库通过 Koin 接收应用现有的跨平台 Settings 实例，不引入数据库迁移或新依赖。设置键存储完整 DTO 和同步状态，解析失败时只清理这两个键并回退到服务端或默认值。

## Risks / Trade-offs

- [本地待同步设置可能长期未上传] → 每次阅读器加载时重新调度待同步快照，网络恢复后继续提交。
- [本地缓存为设备级而服务端设置为用户级] → 服务端同步成功后仍会刷新本地缓存；本变更不扩大账户切换模型，后续如需严格用户隔离可按用户标识命名缓存键。
- [缓冲通道容量有限] → 全局错误仍采用有界缓冲并记录发送失败，避免无界错误风暴占用内存。

## Migration Plan

无需数据迁移。首次读取时若本地缓存不存在，仍从服务端读取并写入缓存；回滚代码后新增 Settings 键会被旧版本忽略。
